## Phase 1: Search Quality + Local Files (v2.14.0)

### 1.1 Rerank Web Search Results

**Problem**: `search` action is the ONLY tool without reranking. `research` and `docs` already use `_rerank_results()`.

**Change**: In `server.py` search action:
1. Fetch `max_results * _RERANK_CANDIDATE_MULTIPLIER` candidates from SearXNG
2. Map `snippet` -> `content` key (reranker expects `content`)
3. Call `_rerank_results(query, results, top_n=max_results)`
4. Filter results with `score < 0.2`
5. Fallback: if reranker unavailable, return original results

**Files**: `server.py` (~15 lines added to search action)

### 1.2 Search Filters

Add 4 parameters to `search` tool:

| Parameter | Type | SearXNG mapping | Example |
|-----------|------|-----------------|---------|
| `time_range` | `str \| None` | Native `time_range` param | `"day"`, `"week"`, `"month"`, `"year"` |
| `language` | `str \| None` | Action-aware routing (see below) | `"en"`, `"vi"`, `"ja"` |
| `include_domains` | `list[str] \| None` | Query prefix `site:` (max 5) | `["github.com"]` |
| `exclude_domains` | `list[str] \| None` | Query suffix `-site:` (max 10) | `["pinterest.com"]` |

**`language` param resolution** (B2 fix): The `language` parameter already exists in the search tool for the `docs` action (library language disambiguation). Reuse the same param with action-aware routing:
- `action="search"` / `action="research"`: pass `language` to SearXNG as native `language` param
- `action="docs"`: pass `language` to docs discovery (existing behavior, unchanged)
- No naming collision -- single param, different semantic per action

**Implementation**:
- Domain filters injected into query string (SearXNG passes through to engines)
- `time_range` passed as native SearXNG API param
- `language` routing based on action type
- Cache key includes all new params

**Files**: `sources/searxng.py` (search function params), `server.py` (action-aware language routing), help docs

### 1.3 SearXNG Config Improvements

In `searxng_settings.yml`:
1. `default_lang: "en-US"` -> `"auto"` (auto-detect from query, important for Vietnamese/CJK)
2. Engine weights:

| Engine | Weight | Rationale |
|--------|--------|-----------|
| Google | 1.5 | Best result quality |
| Brave | 1.3 | Independent index, good for tech |
| Bing | 1.2 | Good complement |
| Startpage | 0.8 | Google proxy |
| DuckDuckGo | 1.0 | Baseline |
| Qwant | 0.6 | Diversity |
| Yahoo | 0.5 | Mostly Bing results |

**Files**: `searxng_settings.yml`

### 1.4 URL Dedup Improvements

In `sources/searxng.py`, before deduplication:

1. **Normalize URL**: strip `www.`, trailing `/`, tracking params (`utm_*`, `fbclid`, `gclid`, `ref`)
2. **Domain cap**: max 3 results per domain (prevent single site dominating)

Add `_normalize_url()` function.

**Files**: `sources/searxng.py`

### 1.5 Local File `convert` Action

Add `convert` action to `extract` tool:

```
extract(action="convert", paths=["/path/to/file.pdf", "/path/to/data.xlsx"])
```

**Parameters**: `paths: list[str]` -- absolute paths, max 10 files.

**Security** (in `security.py`):
- New function `is_safe_local_path(path_str, allowed_dirs) -> Path | None`
- Check order (defense-in-depth):
  1. Reject paths containing `..` (early exit, before resolution)
  2. `Path.resolve(strict=True)` to follow symlinks and canonicalize
  3. `Path.is_file()` check (reject dirs, devices, sockets)
  4. `Path.is_relative_to(allowed_dir)` for each allowed dir (catches symlink escapes)
  5. Size check against `CONVERT_MAX_FILE_SIZE` (default 100MB)
- Optional base directory allowlist: `CONVERT_ALLOWED_DIRS`

**Format support** (expand markitdown extras):

| Format | Extra needed | Status |
|--------|-------------|--------|
| PDF | `[pdf]` | Already supported |
| DOCX | `[docx]` | Already supported |
| PPTX | `[pptx]` | Already supported |
| XLSX/XLS | `[xlsx]` | **New** |
| CSV, JSON, XML, HTML, EPUB | Built-in (no extra) | **New** |
| Images (EXIF metadata) | Built-in | **New** (OCR only with LLM) |
| Audio | `[audio-transcription]` | Deferred to Phase 3 |

**Config** (in `config.py`):
- `CONVERT_MAX_FILE_SIZE: int = 104857600` (100MB)
- `CONVERT_ALLOWED_DIRS: str = ""` (comma-separated, empty = allow all)

**Files**: `security.py`, `sources/crawler.py`, `server.py`, `config.py`, `pyproject.toml`

### 1.6 Dependencies (Phase 1)

| Change | Reason |
|--------|--------|
| `markitdown[pdf,docx,pptx]` -> `markitdown[pdf,docx,pptx,xlsx]` | Spreadsheet support |

No new dependencies. Phase 1 uses 100% existing infrastructure.

## Phase 2: Intelligence Layer (v2.15.0)

### 2.1 Structured Extraction

Add `extract_structured` action to `extract` tool:

```
extract(action="extract_structured",
        urls=["https://example.com/pricing"],
        schema={"type": "object", "properties": {"plans": {"type": "array", ...}}},
        prompt="Extract all pricing plans")
```

**Pipeline**:
1. Extract raw markdown from URLs (reuse existing `extract` action)
2. Truncate content (max 50K chars)
3. Send to LLM with `response_format={"type": "json_schema", "json_schema": {...}}`
4. Validate output with `jsonschema.validate()`

**Fallback chain**: `json_schema` mode -> `json_object` mode + schema in prompt -> Error

**Requires**: LLM available (proxy or SDK mode). Local-only returns clear error.

**New file**: `sources/structured.py`

**New parameters for extract tool**: `schema: dict | None`, `prompt: str | None`

**Files**: `sources/structured.py` (new), `server.py`, `pyproject.toml`, help docs

### 2.2 Query Expansion (Optional, LLM-powered)

Add `expand: bool = False` parameter to `search` tool.

**Pipeline**:
```
Query -> LLM generate 2 alternative queries -> Fetch N results each -> Merge + dedup -> Rerank -> Top K
```

**Implementation**: `_expand_query(query: str) -> list[str]` in `server.py`
- LLM call: max 100 tokens, temperature 0.7
- Fallback: if LLM fails or local mode -> return `[query]` only

**Files**: `server.py`

### 2.3 Find Similar

Add `similar` action to `search` tool:

```
search(action="similar", url="https://example.com/article", max_results=10)
```

**Pipeline**:
1. Extract source page content (reuse `extract`)
2. LLM extract 5-8 keywords + topic from content
3. Search SearXNG with keywords + `-site:{source_domain}`
4. Rerank results by semantic similarity to source content
5. Return top K

**Fallback**: Without LLM, extract `<title>` + `<meta description>` as keywords.

**API design** (B3 fix): Reuse the existing `query` parameter instead of adding a new `url` parameter. For `similar` action, `query` accepts a URL string. Action-aware validation:
- `action="search"` / `action="research"` / `action="docs"`: `query` is required, validated as search terms
- `action="similar"`: `query` is required, validated as URL (must start with `http://` or `https://`)
- This keeps the tool signature clean -- no new parameters, LLMs already know how to pass `query`

**Files**: `server.py`

### 2.4 Snippet Enrichment

Add `enrich: bool = False` parameter to `search` tool.

When enabled:
1. After rerank, take top 5 URLs
2. Check web cache for existing content
3. If not cached, lightweight HTTP GET + extract ~500 chars relevant passage around query terms
4. Replace SearXNG snippets with enriched passages

Default off (adds 2-5s latency). LLM client decides when to enable.

**Files**: `server.py`

## Phase 3: Scale + Polish (v2.16.0)

### 3.1 Jina AI as Priority #1 for Embedding + Reranking

**Embedding auto-detect order** (`_EMBEDDING_CANDIDATES` in `server.py`):
```python
_EMBEDDING_CANDIDATES = [
    "jina_ai/jina-embeddings-v5-text-small",  # NEW: #1 priority
    "gemini/gemini-embedding-001",
    "text-embedding-3-large",
    "embed-multilingual-v3.0",
]
```

**Reranking auto-detect** (`_RERANK_PROVIDERS` in `config.py`):
```python
_RERANK_PROVIDERS: dict[str, str] = {
    "JINA_AI_API_KEY": "jina_ai/jina-reranker-v3",      # NEW: #1 priority
    "COHERE_API_KEY": "cohere/rerank-multilingual-v3.0",
}
```

**Why Jina #1**:
- jina-embeddings-v5-text-small: MMTEB 67.0 (vs Qwen3 ~64.3, Gemini ~63)
- jina-reranker-v3: BEIR nDCG@10 61.94, SOTA for < 1B params
- Single API key (`JINA_AI_API_KEY`) covers both embedding and reranking
- Matryoshka support: request `dimensions=768` for compatibility with existing vector tables
- 131K context for reranking (vs 8K local Qwen3)
- 10M free tokens per new API key

**Dimension compatibility**: Jina v5-text-small's official Matryoshka breakpoints are {32, 64, 128, 256, 512, 1024}. The default `_DEFAULT_EMBEDDING_DIMS=768` is NOT a Matryoshka breakpoint. Handling strategy:

1. **Auto-detect path**: `_init_embedding_backend()` calls `check_available()` which sends a test embedding with `dimensions=768`. If Jina API accepts it (server-side truncation from 1024), Jina becomes the active backend. If Jina rejects 768, `check_available()` returns 0 and auto-detect falls through to the next candidate (Gemini).
2. **Explicit config**: Users who want full Jina Matryoshka quality can set `EMBEDDING_DIMS=1024` (requires `docs_reindex` to re-embed existing chunks).
3. **No code change needed**: The existing auto-detect + fallback chain handles this naturally. Jina is #1 priority but NOT a hard requirement.

**LiteLLM integration**: LiteLLM already supports Jina via `jina_ai/` prefix. No code changes in embedder.py or reranker.py -- only config/server changes.

**Files**: `server.py` (`_EMBEDDING_CANDIDATES`), `config.py` (`_RERANK_PROVIDERS`)

### 3.2 Batch Processing

Add `batch` action to `extract` tool:

```
extract(action="batch", urls=[...up to 50 URLs...])
```

**Components**:

1. **DomainRateLimiter** class (in `sources/crawler.py`):
   - Per-domain concurrency: max 2 simultaneous per domain
   - Per-domain rate: 1 request/second (leaky bucket via `aiolimiter`)
   - Global concurrency: max 10 simultaneous total
   - Uses `asynccontextmanager` pattern

2. **Partial results** via `asyncio.as_completed`:
   - Each URL processed independently
   - Failures don't block other URLs
   - Response: `{results: [...], errors: [...], summary: {total, success, failed}}`

3. **Progress reporting** via `ctx.report_progress(completed, total)`

4. **Limits**: max 50 URLs per call (up from 20 for regular extract)

**Files**: `sources/crawler.py` (`DomainRateLimiter`, batch logic), `server.py` (batch case)

### 3.3 HyDE Embedding (Automatic)

For `docs` search: when FTS5 + vector search returns < 3 results or all scores below `_HYDE_SCORE_THRESHOLD = 0.3`:

1. LLM generates hypothetical answer (200 tokens, temperature 0)
2. Embed hypothetical document
3. Vector search with hypothetical embedding
4. Rerank combined results

No new parameters -- automatic when results are poor and LLM is available.

**Files**: `server.py` (`_do_docs_search`)

### 3.4 Version-Specific Docs Discovery

Pass `version` parameter through discovery pipeline:

| Registry | Version URL pattern |
|----------|-------------------|
| ReadTheDocs | `/{project}/en/{version}/` |
| docs.rs | `/{crate}/{version}/` |
| PyPI | `/pypi/{name}/{version}/json` |

**Files**: `sources/docs.py`

### 3.5 Content Enrichment + Summarization

For `research` action: after reranking top 5 results:
1. Fetch full content (reuse extract/cache)
2. LLM summarize into 200-300 chars factual summary
3. Add `summary` field to each result

Requires LLM. Graceful degradation: skip if no LLM.

**Files**: `server.py` (research action)

### Architecture Note: server.py Bloat Mitigation

`server.py` is already the largest file. Phases 1-3 add significant logic (query expansion, find similar, snippet enrichment, HyDE). To prevent unbounded growth, extract new search strategies into a dedicated module:

- `sources/search_strategies.py` (new): `expand_query()`, `find_similar()`, `enrich_snippets()`, `hyde_embed()`
- `server.py` remains the orchestrator -- calls strategies but doesn't implement them

This keeps each module focused and testable independently.
