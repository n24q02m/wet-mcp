## 2024-05-19 - Safe Batching with Row-Value Lookups in SQLite
**Learning:** When trying to optimize N+1 queries by batching SQL parameter requests using `UNION ALL SELECT`, the large constructed strings are notoriously slow to parse and often lead to SQLite's "too many terms in compound SELECT" limits. Replacing this with row-value lookups like `WHERE (a, b, c) IN (VALUES (?, ?, ?))` is much faster but comes with two very important constraints:
1.  **Syntax:** SQLite requires the `VALUES` keyword inside the parentheses for the list parameter to avoid an `sqlite3.OperationalError` (syntax error).
2.  **Variable Limits:** To support backwards compatibility with older Linux kernels commonly found in CI/CD pipelines (e.g., Ubuntu 20.04), `SQLITE_MAX_VARIABLE_NUMBER` is only 999. Thus, any batched queries must carefully chunk query parameters to stay under 999 variables per execution batch (e.g., maximum batch size of 300 for a 3-parameter composite key constraint).
**Action:** When implementing bulk lookup optimizations with row-value `IN` clauses, explicitly include the `VALUES` keyword and chunk parameter blocks to guarantee safety limits below 900. Also ensure to cast keys to lists if slicing is performed to avoid `TypeError`.
